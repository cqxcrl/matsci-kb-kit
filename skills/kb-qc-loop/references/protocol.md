# QC 批次协议（通用骨架）

> 本文件是随插件发布的**公开泛化协议骨架**，从源库私有 QC 驱动/协议文档中提取：
> 只保留方法论（批次指令模板、干跑/备份/复算纪律、QC 循环步骤与判定纪律），
> 不含任何具体库的批次号、历史语料、台账记录或真实课题。循环入口与命令见 `SKILL.md`。

## 核心任务

对分配的每个 source 页：

1. **读 raw 原文全文**（`sources:` 字段首条 `[[raw/...]]` 指向的文件）
2. **读 source 页全文**
3. **逐条核验**页内的数字、性能指标、排名、因果结论——是否能在 raw 原文中找到支撑

循环目标：核查 ingest 产物里**原文不存在的数字/结论**。

## 判定分级（五级）

| 级别 | 含义 | 判据 |
|------|------|------|
| **VERIFIED** | 数字/结论与原文一致 | raw 中能定位到该数值或等价表述 |
| **MISMATCH** | 数值/单位/对象与原文不符 | 数值原文没有；或数值对但张冠李戴 |
| **STRETCHED** | 原文有，但页内表述**强于**原文 | 如原文"部分样品"→页内"普遍"；原文计算判定→页内"实验验证" |
| **UNSOURCED** | 原文完全找不到该数字/结论 | 🔴 最高危：疑似凭空捏造 |
| **CANT_CHECK** | raw 提取件本身缺该部分（正文缺失、SI 缺失） | 必须标出，不得放行 |

## 纪律（不可违反）

- ❌ **禁止凭领域常识判断**。"这个数值听起来合理"不是通过理由——捏造的数字往往都"听起来合理"。
- ❌ 禁止用 `kb_search` 的结果页替代 raw 原文作为证据。**只看 raw**。
- ✅ 锚定检查：数字必须能在 raw 中逐词命中（含单位变体、量纲换算）。
- ✅ 检查**分母与对象**：原文说的是 A 材料，页内写成 B 材料，同数值也算 MISMATCH。
- ✅ 检查**因果方向**：原文"X 导致 Y"不得写成"Y 导致 X"。
- ✅ 检查**自报 vs 第三方**：作者自报数字须保留自报属性，不得写成领域共识。

## 假阴性形态总表（判定「原文不存在」之前逐项排除）

**「0 命中」不等于捏造。** 判定前必须把下列形态全部试过：

| # | 形态 | 试法 |
|---|------|------|
| 1 | 千分位逗号（`12,708`） | 带逗号 / 不带逗号 |
| 2 | 无分隔（`12708`） | 同上 |
| 3 | 细空格 / 不换行空格（`12 708`） | 普通空格、窄空格 U+2009、不换行空格 |
| 4 | 英文数词（`five thousand`） | 英文数词形态 |
| 5 | 连字 ligature（`Conﬂict`，ﬂ U+FB02） | 归一化后重试 |
| 6 | 分行断字（`permuta-\ntional`） | 删 `-\n` 后重试 |
| 7 | 标点形态（en dash / hyphen / em dash） | 三种横线都试 |
| 8 | 符号/缩写（AI 报告可能自造符号） | 单独 grep 原文 |
| 9 | 小数点空格化（`0 . 6925`，PDF 公式排版产物） | 把 `\s*\.\s*` 归一为 `.` 后重试 |
| 10 | 连字符+CRLF / 连字符+空格（`engi-\r\nneering`、`sci- entific`） | 见下方强制顺序 |

**归一化顺序强制**（顺序错则整批断字漏配，引号命中率显著下降）：

1. **先** `\r\n` → `\n`
2. **再** 删 `-\n`
3. **并**处理 `- `（连字符+空格）

```python
LIG = {"ﬀ": "ff", "ﬁ": "fi", "ﬂ": "fl", "ﬃ": "ffi", "ﬄ": "ffl"}
# 另需：细空格 → 空格或删去；公式系数检索把小数点两侧空格一并归一
```

> 连字误判的严重性高于数字形态误判：它会让页面写下**与事实相反的结论**
> （把「有声明」写成「未声明」），并随下游 concept 页扩散。

## 高危模式与强制做法（从真实事故泛化）

### 1. PDF 表格错位渲染会**主动制造错误的数**

提取件里多列表格常被压成一列，数值与列名**错位相邻**——数字真的在文件里，
逐词检索会命中，但**不属于该表该列**。

- 凡引用「表格中的数」，必须确认该数**所属的列**。
- 发现「数量级差异」的对比时，先怀疑是两张表的数被拼在一起。
- 表格不可读时**不要用邻近的数补位**，标 `> ⚠️ 信息缺口：表格错位，该组数归属不可判定`。

### 2. 「引号伪造」三种变体

引号 = 声称「这是原文」。凡带引号的句子，必须逐词回原文验证（全覆盖，不是抽查）：

| 变体 | 描述 |
|------|------|
| A. 改写拼接后加引号 | 把改写内容用引号包起来冒充原文 |
| B. 跨文献引文错配 | 把 A 论文的话，加引号冠以 B 论文之名 |
| C. 把自算值归给原文 | 拿自己算出的数字去指控原文「不自洽」 |

- 变体 B 检测法：某句在该页 raw 中 0 命中时，**做全库扫描**（`glob raw/**/*.md` 逐份检索）——
  若在别的论文里命中，即为跨文献错配。
- 变体 C 最危险：它把**自己的计算错误伪装成作者的失误**。指控原文「不自洽」之前，
  先确认被指控的数字确实出自原文。

### 3. `sources:` 里的「原文」本身可能是 AI 生成的分析报告

AI 解读报告看起来像论文（有标题、期刊、作者、图表讨论），但证据等级**低于普通二手转述**。

- 识别指纹（文件头 3000 字符内检索）：`type: literature-note`、`mode: 精读/速读/深度`、
  标题含「AI 文献分析报告」。工具：`python tools/qc_find_ai_deps.py`。
- 凡 raw 含上述指纹 → 在 `source_reliability` 显式标注证据等级。
- 该页出现的**符号/缩写单独作为 grep 目标**去论文原文验证（符号是 AI 自造的典型产物）。
- 能补一手原文的优先补；补不到的，该页不得作为综述写作的定量依据。

### 4. 错误会沿 wikilink 向下游 concept/topic 页传播

- 改完 source 页后，用 `python tools/kb_backlinks.py --page <页面名>` 查入站链接。
- 逐个打开下游 concept / topic / entity 页，确认是否复述了被推翻的结论；已传播 → 同步修正。
- **只修 source 不修下游 = 只做了一半**（上游一个错误常连带数处副本，多在批次名单之外）。

### 5. 「首条是 `raw/clippings/`」≠「二手解读」

clippings 里混装出版商全文 HTML（含 Methods/Results/Discussion/References 章节，**等同一手原文**）
与公众号解读（含 `mp.weixin.qq.com`/「点击上方」/「阅读原文」，**二手转述**）。
**看文件内容，不看目录名。**

### 6. 页面「自我降级」

页面明明引用了学术来源，却自称「唯一依据是二手解读稿」。见到这类声明，
**必须先开箱核对该页 `sources:` 里的每个文件**，再决定声明是否成立。
不要因为页面自称不可靠就不去核对。

### 7. 「只读摘要就写批判性评估」

免责声明会**掩盖核对缺失**：写成「依据二手转述」后，批判性评估反而变成不受约束的臆断。

- 写批判性评估前必须先拿到一手全文；只有摘要时，只能写摘要层面可见的问题。
- 不得以「依据二手转述」的免责声明结案——免责不等于免责**任**。
- 每一条指控都要能指出原文位置；指不出就降级为「信息缺口」。

### 8. 付费墙不是终点

经 OpenAlex / Crossref / Unpaywall 取官方摘要后，仍能核验大部分核心论断、
精确定位不可核的数字、核对 DOI/标题/卷页/日期/机构数。付费墙页一律做这一轮，不要直接放弃。

### 9. 「计数类断言」也需锚定

「列出 N 项」「共 N 篇」与数值类断言同等需要锚定（PDF 表格可能丢行）。
锚不到就改为不依赖计数的表述，不要保留无法核验的数字。

## 就地修正规则

发现 MISMATCH / UNSOURCED / STRETCHED 时：

- **改写为原文的准确表述**（若原文有对应说法）。
- **若原文确无 → 删除该数字或结论**，并在原位置加批判性标记：
  - `> ⚠️ 信息缺口：...`（资料不足，无从判定）
  - `> ⚠️ 二次引用失真：...`（转述强于原文）
  - `> ⚠️ 单源论断：...`（只有一篇支撑）
  - `> ⚠️ 自报数字：...`（作者自报无核验）
- 标记格式遵循 CLAUDE.md §批判性标记：块引用 `> ⚠️ 类型：...` 或列表项内行内
  `**⚠️ 类型：** ...`，**同一页内保持一致**。
- **标记就地贴在具体句子/数字旁**，不要在文末堆成清单。

## frontmatter 更新

- `updated`：改为当天日期。
- 发现重大问题：追加/修订 `source_reliability`（**长文本必须整体加双引号**——
  含冒号会导致整个 frontmatter 解析失败）。
- 大幅修正加 `qc_status: fixed`；仅核验通过加 `qc_status: verified`。

## 批次指令模板

### 证据升级型（二手 → 一手原文）

```
你是知识库证据升级核查员。工作目录为知识库根（以当前实际库根为准）。
先读 skills/kb-qc-loop/references/protocol.md（判定分级与纪律）。

本批 N 个页面：<列表>，均在 wiki/sources/ 下。

对每页执行：
1. 读该页 frontmatter 的 sources: 字段，列出全部 raw 项
2. 区分：哪些是二手转述（公众号剪藏等），哪些是论文原文（一手）——看内容，不看目录名
3. 若该页已有论文原文但未被列为来源：
   a. 读论文原文全文与二手解读全文
   b. 逐一比对页内数字：以论文原文为准
   c. 把论文原文补进 sources: 字段（列表首位，格式 "[[raw/...]]"）
   d. 修正与论文原文不符的数字；冲突处加 > ⚠️ 二次引用失真：
4. 若该页只有二手来源：
   a. 按页面的 doi / source_url / 论文标题检索一手原文
   b. 找到 OA 全文 → 提取存入 raw/ 对应目录，补进 sources: 首位
   c. 找不到 → 在页面加显著二手来源标记，不得假装核查过
5. 修正 frontmatter：updated: <当天>、qc_status: fixed（有改动）或 verified（无改动）

二手来源的强制标记（找不到一手原文时）：
在页面 ## 诚实边界 节（没有就新建）加：
> ⚠️ 二手来源：本页唯一证据来源为二手解读（<文件名>），非同行评审原文。
> 页内数字均属经一手转述后的二手数据，未经原文核验。综述引用前须回查原始文献。
并在 frontmatter 的 source_reliability 中写明该限制（长文本必须整体加双引号）。

纪律：不得凭领域常识判断数字是否合理；不得用 kb_search 结果页替代原文证据。
完成后返回：每页一行的结论 + 统计（补到一手原文 N 页 / 未补到 N 页 / 修正数字 N 处）。
```

### 标准证据回溯型（已有一手原文）

```
你是知识库质量核查员。工作目录为知识库根（以当前实际库根为准）。
先读 skills/kb-qc-loop/references/protocol.md。

本批 N 个页面：<列表>，均在 wiki/sources/ 下。

对每页：
1. 从 sources: 取论文原文路径（非二手剪藏），读全文
2. 逐条核验页内数字/性能指标/材料名/排名/因果结论，在原文中锚定
3. 重点盯：① 凭常识补全的数字 ② 归因错配 ③ 分母口径不自洽 ④ 二次引用失真 ⑤ 证据源错配
4. 就地修正；updated: <当天>；qc_status: fixed 或 verified
5. 修正处加就地标记（> ⚠️ 自报数字：/ > ⚠️ 矛盾：/ > ⚠️ 单源论断： 等）

纪律：禁止凭领域常识放行；数字须在原文逐词命中（含单位变体/量纲换算）；
不得用检索结果页替代原文。YAML 长文本字段必须整体加双引号。
完成后返回结构化清单 + 统计。
```

## 批次与限流

- **一次只跑一个 agent**；**绝不并行启动多个 agent**（并行曾触发 API 限流被中断）。
- **单批页数 ≤ ~12 页**（实测单次处理 12–15 页不超上下文）。
- 节奏建议：**会话级 cron 每 25 分钟唤醒一次**，每 tick 推进一个批次；
  除非用户明确要求提速，不要自定义更高频节奏。
- 每 tick 的动作顺序：
  1. 读 `.qc/queue.json` 与 `.qc/LEDGER.md`，找**第一个未完成**的批次
  2. 读该批次的页面清单
  3. **启动 1 个 agent**（后台运行）执行该批次
  4. 在 `.qc/LEDGER.md` 把该批次标为 🔄
  5. 本轮结束；下次唤醒时检查其落盘结果并标 ✅
- **若发现已有 agent 仍在运行 → 不要启动新 agent，直接结束本轮，等下次唤醒。**
- 某批被限流中断 → **下一 tick 重跑同一批次，并把该批拆成两半**。
- **死亡判定靠 tick 计数（stall）**：建议 4 tick 无落盘进展即判死亡并重跑；
  产物 `.qc/last_tick.json`（已评分页数 + 停滞计数），递增/清零规则由调度方定义并写进台账。
  曾有一批在会话中断中死亡且未落盘任何产出——这就是「上批是否仍在运行」必须每 tick 核实的原因。

### queue.json 最小 schema

```json
{"B1": ["页名1", "页名2"], "B2": ["页名3"]}
```

结构 = `{批次名: [页名, ...]}`（页名为 wiki 页面 basename，不带 `.md` 后缀）；
创建方式：用户/调度方手写或脚本生成后落 `.qc/queue.json`（落点走 `kb_lib.qc_work_dir`），插件不附带任何现成队列。

### 停止条件

全部批次 ✅ → 进入汇总阶段（报告 + 索引重建 + 日志）→ 删除 cron 任务。

## 写盘纪律（干跑 / 备份 / 复算）

- 默认**干跑**；`--apply` 才写盘。
- 写前备份到 `.qc/backups/YYYYMMDD/`（走 `kb_lib.backup_root()`，**不手拼路径**）。
- **写后复算**：重读核对；frontmatter 必须仍可解析且字段数不减。
- 归档层**只进不出**，绝不原地改写；新产出写库根 `.qc/`。
- **写盘脚本改动前先跑 `--selftest`**（已知答案正反例反算）——
  「计数器自己出错」曾被多次误读成内容质量问题。

## 输出要求

返回**结构化清单**（不要只给散文总结），每页一节：

```
### <页面名>
raw: <raw 路径>  (size)
结论: PASS | FIXED | BLOCKED
issues:
- [UNSOURCED] "页内原句摘录" → raw 中 grep "<关键词>" 命中 0；处置：已删除/已改写为 "..."
- [MISMATCH] 页内数值 → 原文数值（对象/口径差异）；处置：已改写
- [CANT_CHECK] raw 提取件无正文，仅摘要；处置：已加 ⚠️ 信息缺口
fixed_count: N
```

## 完成判据

- 每页都给出结论
- 每处修改都能指出 raw 中的依据（或明确说明 raw 中无依据）
- 无「未读原文即判定」的页面
